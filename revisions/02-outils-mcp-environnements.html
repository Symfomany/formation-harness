Règles de la propriété tools
  • Absente ou ["*"] : tous les outils, y compris MCP.
  • [] : aucun outil.
  • Liste : seulement ceux-là. Un nom inconnu est ignoré sans erreur.
  • Outil MCP : serveur/outil ; tous les outils d'un serveur : serveur/*.
  • Serveurs MCP intégrés au cloud agent : github (lecture seule, jeton limité au dépôt) et playwright (localhost seulement).

Emplacements : dépôt .github/agents/ ; organisation ou entreprise : dépôt .github-private, dossier agents/. En cas de conflit de nom, le niveau le plus bas gagne (dépôt > organisation > entreprise). Version d'un agent = SHA du commit du fichier ; une PR garde la même version de l'agent pendant toute sa vie.

Vérifier : journal de session du cloud agent, étape Start MCP Servers (outils réellement chargés).

Serveur MCP GitHub

  • Distant : https://api.githubcopilot.com/mcp/. Lecture seule : /mcp/readonly (ou en-tête dédié). Limiter les jeux d'outils : en-tête X-MCP-Toolsets.
  • Dans le cloud agent : intégré, lecture seule, limité au dépôt courant. Pour l'élargir : jeton dédié (ex. secret COPILOT_MCP_GITHUB_PERSONAL_ACCESS_TOKEN) avec le minimum de droits, ou une GitHub App.

Registre et liste d'autorisation

  • Politique organisation / entreprise : activer ou non les serveurs MCP dans Copilot.
  • Registre MCP : URL d'un registre approuvé ; politique Allow all ou Registry only (seuls les serveurs du registre sont utilisables).
  • Copilot code review n'utilise que des outils MCP marqués en lecture (readOnlyHint: true).

copilot-setup-steps.yml

À connaître par cœur
  • Chemin .github/workflows/copilot-setup-steps.yml, sur la branche par défaut.
  • Un seul job, nommé exactement copilot-setup-steps.
  • Clés prises en compte : steps, permissions, runs-on, services, snapshot, timeout-minutes (max 59).
  • Étape en échec : les suivantes sont sautées, l'agent démarre quand même.
  • fetch-depth de checkout : remplacé par Copilot.
  • Runners : Ubuntu x64, Windows 64 bits, plus grands runners ; pas de macOS.
  • Secrets et variables utilisés : ceux de type Agents.

Portée par dépôt et par branche

  • Le cloud agent ne modifie que le dépôt où la tâche a démarré.
  • Nouvelle tâche : branche copilot/... créée, seule branche où il peut pousser. @copilot sur une PR existante : il pousse sur la branche de cette PR.
  • Il est soumis aux protections de branche et checks requis. Un ruleset incompatible (ex. auteurs de commit restreints) bloque l'agent : ajouter Copilot en bypass actor si c'est voulu.

Invoquer un agent en CI

- run: npm install -g @github/copilot
- env:
    COPILOT_GITHUB_TOKEN: ${{ secrets.COPILOT_CLI_TOKEN }}
  run: copilot -p "..." --allow-tool='shell(git:*)' --allow-tool=write --no-ask-user

Jeton : PAT fin avec la permission Copilot Requests. Alternative recommandée : GitHub Agentic Workflows (engine: copilot, agent en lecture, safe outputs).

Pièges

Les erreurs classiques
  • servers (VS Code) vs mcpServers (cloud agent) : la question peut piéger sur la clé.
  • Croire qu'un secret de dépôt classique est visible par la configuration MCP : il faut un secret Agents préfixé COPILOT_MCP_.
  • Mettre tools: ["*"] sur un serveur MCP qui a des outils d'écriture : le cloud agent les utilisera sans approbation.
  • Nommer le job autrement que copilot-setup-steps, ou laisser le fichier sur une branche de travail : ignoré.
  • Penser qu'une étape de setup en échec bloque l'agent : il démarre quand même (et risque d'échouer plus loin).
  • Attendre timeout-minutes: 90 : plafond à 59.
  • Réessayer en boucle une erreur déterministe (test cassé, droit manquant) : il faut escalader.
  • handoffs dans un agent destiné au cloud agent : ignoré.

Trucs et astuces

Raisonnements rapides
  • « L'agent n'arrive pas à installer une dépendance » : la préinstaller dans copilot-setup-steps, ou ajouter le domaine à la liste du pare-feu.
  • « L'agent doit lire des issues d'un autre dépôt » : le MCP GitHub par défaut ne le permet pas ; jeton dédié en lecture seule.
  • « Limiter l'agent à la lecture d'un outil externe » : tools listant uniquement les outils en lecture + serveur en mode lecture seule.
  • Toute question « CI + agent » : demandez-vous quel jeton, quelles permissions, qui approuve.
