Cloud agent : les protections

  • Seuls les utilisateurs avec accès en écriture le déclenchent.
  • PR brouillon ; il ne fusionne pas, n'approuve pas.
  • Le demandeur ne peut pas approuver ; approbation supplémentaire si la PR n'est attribuée à personne.
  • Workflows : « Approve and run workflows » par défaut.
  • Validation intégrée : CodeQL, Advisory Database, secret scanning, Copilot code review (sans licence GHAS, désactivables une à une).
  • Ruleset incompatible : ajouter Copilot en bypass actor de ce ruleset.
  • Commits signés, auteur Copilot, demandeur en co-auteur, lien vers le journal de session.
  • Pare-feu ; caractères cachés filtrés.

GitHub Actions : les pièges

  • Événements créés avec GITHUB_TOKEN : ne déclenchent pas d'autres workflows (sauf workflow_dispatch, repository_dispatch).
  • Check requis + filtre paths : statut jamais reçu, PR bloquée.
  • Entrées : via env:, jamais ${{ }} dans run:.
  • Revert d'un commit de fusion : git revert -m 1 <sha>.
  • Environnement protégé : approbateurs + « Prevent self-review » + branches autorisées.
  • Créer une PR depuis Actions : « Allow GitHub Actions to create and approve pull requests ».
Les sept réflexes
  1. Imposer par un mécanisme plutôt que par une consigne.
  2. Moindre privilège.
  3. Humain sur l'irréversible, et seulement là.
  4. Trace durable et inspectable.
  5. Preuves (CI, scan, journal) plutôt qu'affirmation de l'agent.
  6. Annuler sans réécrire l'histoire.
  7. Corriger la cause, une chose à la fois.
