Une bonne tâche pour un agent autonome

Bonnes candidates (well-scoped tasks) : corrections de bugs, tests manquants, documentation, accessibilité, dette technique, petites évolutions avec critères d'acceptation clairs.
Mauvaises candidates : tâches larges et transverses, ambiguës, sensibles (sécurité, données personnelles, authentification), incidents de production, tâches qui exigent une connaissance métier non écrite.

Une issue bien écrite pour un agent contient : le problème, le résultat attendu, les critères d'acceptation, les fichiers ou zones concernés, les contraintes (ce qu'il ne faut pas toucher), comment vérifier.

Exemple concret

Le lot 2 doit être réécrit. Architecture retenue dans la formation :

  1. planificateur-backlog produit plan-lot2.md (PROPOSÉ). Il ne lance rien.
  2. Le chef de projet relit avec la grille et écrit APPROUVÉ par … le ….
  3. Le reviewer diagnostique (lecture seule + revue.md). Point de validation.
  4. Le rédacteur réécrit. Le hook postToolUse renvoie les erreurs de format immédiatement.
  5. PR ; checks requis ; revue humaine ; fusion ; publication après approbation de l'environnement.

Chaque étape laisse une trace dans l'outillage standard : fichier, commit, PR, check run, release.

Pièges

Les erreurs classiques à l'examen
  • Croire que le cloud agent peut fusionner, approuver ou passer sa PR en « prête » : non, jamais.
  • Croire que Copilot code review peut « Approuver » ou « Demander des changements » : il laisse toujours une revue de type Comment, qui ne compte pas dans les approbations requises.
  • Choisir « ajouter une phrase aux instructions » pour empêcher une action dangereuse : une instruction guide, elle n'impose pas.
  • Choisir « exiger une approbation humaine à chaque étape » : cela ralentit sans réduire le risque. L'examen valorise les approbations ciblées.
  • Confondre plan dans le chat et plan inspectable : le bon plan est un artefact (fichier, commentaire, PR).

Trucs et astuces

Pour aller vite le jour J
  • Question « où placer l'humain ? » : sur ce qui est irréversible ou conforme / sensible. Ailleurs, des contrôles automatiques.
  • Question « comment rendre observable ? » : la réponse cite un objet GitHub standard (PR, commit, check, artefact, journal de session, audit log).
  • Pour itérer sur une PR de Copilot sans le relancer à chaque commentaire : regrouper les commentaires dans une revue (Start a review), puis la soumettre.
